Developer integration

How ParkourFlux uses the TikTok API

The ParkourFlux publishing tool is a first-party, single-operator application. It exists to upload videos that ParkourFlux produces to ParkourFlux's own TikTok account. It is not offered to third parties, has no other users, and does not read or collect anyone else's content.

Single-account scope. The application is authorised by one TikTok account — the account that owns this channel — and can act only on that account. There is no sign-up, no user directory, and no mechanism for another person to connect an account.

Permissions requested, and what each is for

ScopeWhy it is needed
user.info.basic Confirms which account the tool is authorised against, so a video cannot be uploaded to the wrong destination, and surfaces the creator's available privacy settings before a post is prepared.
video.upload Uploads a finished video into the account's own drafts/inbox. The operator then opens TikTok and posts it manually. This is the current mode of operation.
video.publish Requested so an already-approved video can be posted directly on a schedule instead of requiring a manual tap. The video is reviewed and approved before the API is called — this removes a manual step, not the review.

The publishing flow

  1. A video is produced The pipeline renders a finished vertical video. Nothing has touched TikTok yet.
  2. The operator approves it The finished file is reviewed and explicitly approved. Rejected videos are never uploaded.
  3. It is uploaded The approved file is sent to the account's own TikTok drafts. Under direct post, the same approved file is published straight to the account.
  4. The result is logged Success or failure is written to a local log. Failures stop the run rather than retrying.

Privacy settings are respected

Before preparing a post, the tool queries the creator's available privacy options and will not select a level the account is not permitted to use. If the requested level is unavailable, it falls back to the most restrictive option the account allows rather than publishing more widely than intended.

What data is stored, and where

  • An OAuth access and refresh token for the single authorised account, stored locally on the operator's own machine in a file that is excluded from version control. It is never transmitted anywhere except to TikTok.
  • A local publishing log recording which of our own videos were uploaded and when.

No TikTok user data is collected, no analytics about other accounts are gathered, no content belonging to anyone else is read or downloaded, and nothing is shared with third parties. There is no server-side database — the tool runs on a single machine.

Revoking access

Access can be withdrawn at any time from the TikTok account's Security & permissions → Manage app permissions screen. Revocation takes effect immediately; the stored token stops working and the tool can no longer upload.
